# Gen3 Endpoint implementation plan

> **Deferred** until [2026-11-23-gen2-up-dp-rc.md](2026-11-23-gen2-up-dp-rc.md) is closed. Do not start these tasks while that plan is active. Equalization needs the Downstream master from that plan.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring `rivet_pcie_ctrl` to Gen3 x4 Endpoint in simulation, with L0, one posted write, and one completion, while every current Gen2 smoke still passes.

**Architecture:** Gen3 stays on the 250 MHz PIPE clock and widens the pipe to 32 bits per lane. Ordered sets and TLP framing move from 8b/10b K-symbols to 128b/130b blocks (`txstart_block`, `txsync_header`, `txdata_valid`). The LTSSM reaches 8 GT/s through Recovery.Speed and the four Recovery.Equalization phases, then the existing DLL sequence number and LCRC ride inside the new frame tokens. Gen2 remains the default build. Gen4 protocol is out of this plan.

**Tech Stack:** SystemVerilog, `rivet_pkg`, Questa UVM, Verilator lint.

## Global Constraints

- English only in code, comments, and docs.
- `MODE=EP`. Lanes stay in {1, 2, 4}. No vendor cells in `rtl/pcie_ctrl/`.
- Default elaboration stays Gen2, 16-bit PIPE. A Gen3 test passes `GEN=3` and `PIPE_DATA_WIDTH=32`.
- Do not widen the user AXI-ST ports. They stay 64-bit.
- Do not implement Gen4 (16 GT/s, 64-bit PIPE) or Gen5.
- Do not paste proprietary spec text into the tree. `specs/` stays untracked.
- A Gen2 smoke that passes today must still pass after each slice.
- Quote timing and megabytes per second only from a run that printed them.

## What the local documents fix

Reviewed, not copied: PG239 (UltraScale+ PHY), PG213 (integrated block, LTSSM codes and pipe-width note), the Gen4 base book for the 8 GT/s rules it still carries, and the MindShare PCIe 3.0 and PIPE notes. There is no separate Base 3.0 PDF in `specs/`. Gen2 books stay the regression reference.

Locked from those documents for this plan:

- Line rate 8.0 GT/s. Encoding 128b/130b. `phy_pclk` stays 250 MHz from Gen2 through Gen4.
- UltraScale+ `phy_txdata` is 64 bits wide on the pin, but bits [31:16] are the Gen3 half and bits [63:32] stay unused until Gen4. Gen1/Gen2 keep using [15:0]. `txdatak` is Gen1/Gen2 only.
- A 128b block starts at bit 0 of the pipe word. The PHY samples `txsync_header[1:0]` when `txstart_block` is high. `txdata_valid` low means the PHY ignores that cycle. On UltraScale+, `rxstart_block` is 2 bits; at Gen3 only `01` (block starts in the low 32 bits) is legal. `10` is a Gen4 upper-half start.
- PG239 equalization is not the PIPE LF/FS handshake. The MAC asks the PHY with the assist/EQ ports in PG239 Chapter 4. The first simulation does not model a GT. It completes the LTSSM phases against the UVM peer.
- PG213 codes for the new states: `6'h28` Phase 0, `6'h29` Phase 1, `6'h2A` Phase 2, `6'h2B` Phase 3. Recovery.Speed is already `6'h0C`.

`rivet_gen_e` currently jumps from `RIVET_GEN2` to `RIVET_GEN4`. `rivet_pipe_if` already has `PIPE_DATA_WIDTH` and the Gen3 block ports, and nothing drives them.

## Slice 1 — Gen3 is a legal elaboration

Gen2 binaries and smokes stay the default. This slice only makes `GEN=3` compile.

- [ ] Add `RIVET_GEN3 = 3` to `rivet_gen_e` in `rtl/pcie_ctrl/rivet_pkg.sv`. Add the four EQ enumerators next to `RIVET_LTSSM_RECOVERY_SPEED` using the codes above.
- [ ] Find every `$error` or generate that rejects `GEN != 2`. Allow 2 and 3. Leave 4 and 5 rejected.
- [ ] Add a width rule in the package: Gen2 pipe width is 16, Gen3 pipe width is 32. A mismatched pair is an elaboration error.
- [ ] Run `scripts/lint.ps1` at the default Gen2 settings. It must still print `PASS: Verilator lint (controller)`.
- [ ] Elaborate once with `GEN=3` and `PIPE_DATA_WIDTH=32` (a one-line Verilator command or a lint plusarg, no new test yet). Commit: `build(pkg): allow Gen3 elaboration`.

## Slice 2 — 32-bit block pipe, Gen2 untouched

The MAC still speaks 8b/10b at Gen2. At Gen3 the adapter presents 32-bit words plus block sideband. No LTSSM change yet; a unit-level check drives the adapter.

- [ ] In `rivet_mac_pipe_adapter.sv`, when `rate` is Gen3, drive `txdata[31:0]`, pulse `txstart_block` on the first word of a block, present `txsync_header` in that cycle, and use `txdata_valid`. When `rate` is Gen2, those Gen3 signals stay idle and `txdatak` behaves as it does today.
- [ ] On RX, accept a block only when `rxdata_valid` is high and `rxstart_block` is `01`. Ignore a cycle with `rxdata_valid` low. Do not treat `10` as a Gen3 start.
- [ ] Extend the PIPE peer with a Gen3 block send/receive task that is not called from Gen2 tests.
- [ ] Add `tb` coverage that one 16-byte block with sync header `2'b10` (ordered set) and one with `2'b01` (data) round-trips through the adapter. Gen2 `smoke_gen2_x1` still reaches L0.
- [ ] Commit: `feat(mac): add the Gen3 32-bit block pipe`.

## Slice 3 — Ordered sets at 8 GT/s

Training sets change shape. The Gen2 COM/K-symbol path stays behind `rate == Gen2`.

- [ ] Teach `rivet_mac_os_tx.sv` to emit a Gen3 TS1/TS2 as a 16-byte block: sync header for an ordered set, rate-id bit for 8 GT/s, lane and link numbers in the same fields the Gen2 peer already checks, plus the equalization fields Slice 4 will fill with zeros until then.
- [ ] Teach `rivet_mac_os_rx.sv` to recover block lock from `rxstart_block` and to parse that TS into the existing rate-id, lane-number, and link-number outputs.
- [ ] Emit a Gen3 SKP ordered set between packets once L0 exists. Do not insert it mid-block.
- [ ] Directed UVM: peer sends four TS1 blocks at Gen3, scoreboard sees the same rate id and lane number. No L0 requirement yet.
- [ ] Commit: `feat(mac): decode Gen3 training blocks`.

## Slice 4 — Recovery.Speed and Equalization

Endpoint is the upstream port. The directed peer plays the downstream port. No analog eye, no preset search. One fixed preset is enough to walk the states.

- [ ] From L0 at Gen2, enter Recovery, then Recovery.Speed. Set PIPE rate to Gen3, wait for `phystatus`, and change the active width to 32. This is the same PhyStatus handshake Gen2 already uses for the Gen1/Gen2 speed change.
- [ ] Phase 0 (`6'h28`): send TS1 at 8 GT/s with the starting preset. Leave when the peer's TS1 shows the same speed and the block lock from Slice 3 is set.
- [ ] Phase 1 (`6'h29`): stay at 8 GT/s until the peer requests the next phase in its TS1.
- [ ] Phase 2 (`6'h2A`): accept the peer's coefficient or preset request on the TS1 fields and echo the request in the next TS1. Advance when the peer sets the phase-2 successful indication.
- [ ] Phase 3 (`6'h2B`): send the request toward the peer's transmitter the same way, then follow the peer into Recovery.RcvrLock / RcvrCfg / Idle and back to L0 with rate still Gen3.
- [ ] On a missing peer indication, return to Recovery.Speed at Gen2. Do not invent a timeout shorter than the Gen2 recovery timers already in `rivet_ltssm.sv`.
- [ ] Test `smoke_gen3_l0_x4`: Gen2 L0, then this directed speed change, `cfg_ltssm_state` reads L0, pipe rate is Gen3. `smoke_recovery_speed_gen2_x4` still passes.
- [ ] Commit: `feat(ltssm): reach Gen3 L0 through equalization`.

## Slice 5 — One TLP each way at Gen3

DLL sequence numbers and LCRC do not change. The symbol layer does: Gen3 uses frame tokens in a data block instead of STP/END K-symbols.

- [ ] In the MAC TX path, when rate is Gen3, put the existing DLL beat stream into data blocks (sync header `2'b01`) and mark the packet with the Gen3 frame token instead of K28.2 / K29.7. Gen2 STP/END stays on the K path.
- [ ] On RX, a data block feeds the same DLL byte stream the Gen2 path uses after the token is stripped. `txdata_valid` low cycles are not bytes.
- [ ] `smoke_gen3_memwr_x4`: after Slice 4's L0, one 1 DW MemWr32, peer sees the payload, UVM error count 0.
- [ ] `smoke_gen3_cpld_x4`: one 1 DW CplD returns on RC, scoreboard tag matches. The Gen2 `smoke_tlp_rq_rc_gen2_x4` still passes.
- [ ] Update `docs/gen-evolution.md` and `docs/roadmap.md` so the active sim target is Gen3 EP x4 and Gen4 stays next. Do not claim a board or a megabyte-per-second number.
- [ ] Commit: `feat(dll): carry a Gen3 TLP in 128b/130b blocks` and `docs(roadmap): open the Gen3 EP track`.

## Explicitly later

These are not required for the first Gen3 L0 and are separate plans:

- PG239 `txeq_*` / `rxeq_*` assist tied to a generated PHY, and a VCU118 or VMK180 rebuild. Simulation L0 does not need a GT.
- Gen3 SKP interval tuning beyond "between packets", EIEOS, and electrical-idle exit.
- Payload sweeps and a new README curve. The Gen2 4 ns numbers stay as they are.
- 64-bit PIPE, 16 GT/s, and Gen4 equalization.
- FLR, INTx, and the other PG213 holes already listed for Gen2. Gen3 does not close them.
