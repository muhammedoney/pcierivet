# Soft PHY (PG239 replacement) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Xilinx PG239 PCIe PHY on VCU118 with a Rivet PHY that presents the same PIPE ports, covers Gen1 through Gen4, and keeps every digital PHY function in RTL.

**Architecture:** The MAC stays `rivet_pcie_ctrl` and still ends at PIPE. A new soft PCS (`rivet_phy_pcs`) implements Original PIPE: 8b/10b, 128b/130b, comma and block lock, the elastic buffer, receiver detect, electrical idle, rate and power handshakes, and the equalization ports. A PMA port underneath the PCS is either a behavioral model (simulation) or `GTYE4_CHANNEL` / `GTYE4_COMMON` (VCU118). The serial PMA, CDR, PLL, TX driver, and RX analog equalizer stay in the GTY primitive. That is the softest split the FPGA allows. PG239 is not instantiated.

**Tech Stack:** SystemVerilog, `rivet_pkg`, Verilator for the PCS, Vivado for the GTY elaborate on `xcvu9p-flga2104-2L-e`. Questa UVM stays on the controller and is not the PHY gate.

## What this PHY must match

Reviewed from `docs/gen-evolution.md`, `docs/pipe-notes.md`, `rtl/interfaces/rivet_pipe_if.sv`, and the VCU118 shell. Locked here:

| Rate | Line | Coding | PCLK | PIPE bits used / lane | PMA word to the PCS |
|------|------|--------|------|------------------------|---------------------|
| Gen1 (`3'd0`) | 2.5 GT/s | 8b/10b | **125 MHz** | low 16 | 20-bit line code |
| Gen2 (`3'd1`) | 5.0 GT/s | 8b/10b | 250 MHz | low 16 | 20-bit line code |
| Gen3 (`3'd2`) | 8.0 GT/s | 128b/130b | 250 MHz | low 32 | 32-bit raw |
| Gen4 (`3'd3`) | 16 GT/s | 128b/130b | 250 MHz | 64 | 64-bit raw |

Gen1 is the one rate whose PCLK is not 250 MHz. PG239 changes PCLK, not the 16-bit width, between Gen1 and Gen2. A width-16 PHY accepts rates 0 and 1. A width-32 PHY accepts 0, 1, and 2. A width-64 PHY accepts 0 through 3. A higher rate than the elaborated width is an elaboration `$error`.

Gen3 and Gen4 PIPE data is not packed solid. 128 bits of block data occupy 130 bit-times on the wire. At 250 MHz that is 64 cycles with `txdata_valid` / `rxdata_valid` high and one cycle low, then the pattern repeats. The PCS inserts and strips that idle cycle. The MAC already drives `txdata_valid`.

`phy_pclk` is the PIPE clock: 125 MHz at Gen1, 250 MHz at Gen2, Gen3, and Gen4. `user_clk` is a second `BUFG_GT` output. For the x4 builds Rivet uses, its frequency is also 250 MHz. PG239 keeps `phy_pclk` edge-aligned with `user_clk` and does not phase-align them. The simulation model may drive both from `pclk_in`. The GTY wrapper must not tie the two nets together.

## Locked from PG239 v1.0 (December 18, 2024)

Read against `specs/pg239-pcie-phy-en-us-1.0.pdf`. These override the earlier guesses in this plan.

- PLL, fixed by the guide: Gen1 is CPLL and does not use a GT common. Gen2 default is QPLL1 (CPLL is the other legal choice). Gen3 is QPLL1. Gen4 is QPLL0. One common per quad. Lane 0 is the master and must stay active. The quad is not shared.
- `phy_refclk` comes from `BUFG_GT`. `phy_gtrefclk` comes from `IBUFDS_GTE4`. Both are 100 MHz on VCU118. `gt_gtpowergood` drives the `CE` of that `BUFG_GT`.
- Reset holds `phystatus` high and asynchronous until the GT finishes. `phystatus_rst` rises immediately and falls only after CPLL/QPLL lock, progdiv reset done, TX/RX reset done, and a TX sync of four refclk cycles. Every other `phystatus` is a one-cycle pulse.
- `powerdown` is per-design, not per-lane. P2 is unsupported. P0s is unsupported when the maximum speed is Gen3 or Gen4. Beacon is unsupported. The RX elastic buffer is always in the path.
- Receiver present for the Rivet MAC is `rxstatus = 3'b011` sampled with `phystatus`. That is Table 10 and `RIVET_RXSTATUS_RX_DETECTED`. Table 9 of the same guide says `001` for present and `000` for absent. The soft PHY follows Table 10 so `rivet_mac_pipe_adapter` can leave Detect.
- `txcompliance` forces running disparity negative. It does not insert a decode error.
- `txeq_ctrl`: `00` idle, `01` preset, `10` coefficient, `11` query. The MAC returns the ctrl to `00` when `txeq_done` is high. Default preset, if ctrl never selects one, is `4'h4`.
- `txeq_coeff[5:0]` is loaded across three PCLK cycles: pre-cursor, then main-cursor, then post-cursor. `txeq_new_coeff[17:0]` is `{pre[5:0], main[5:0], post[5:0]}`.
- `rxeq_ctrl`: `00` idle, `01` reserved, `10` RX EQ, `11` RX EQ bypass. `01` is not a preset apply. Both `rxeq_done` and `rxeq_adapt_done` high means success. `rxeq_done` high with `rxeq_adapt_done` low means the MAC must ask again. `rxeq_preset_sel` is 1 for a preset reply (low 4 bits valid) and 0 for a coefficient reply.
- Preset apply (`txeq_ctrl = 01`) and query (`txeq_ctrl = 11`) happen after `txelecidle` and before `rate` changes. Gen3/Gen4 EQ settings are not kept across a rate change.
- The MAC, not the PHY, deskews lanes. The MAC must not use the rising edge of `rxelecidle` as electrical-idle entry. Gen3 and Gen4 TX SKP ordered sets are 16 symbols, which is a MAC rule.
- RX is DFE by default. An add-in card uses the 20 dB insertion-loss setting. VCU118 is that case. Gen4 wants a -2, -2L, or -3 speed grade. The board part `xcvu9p-flga2104-2L-e` qualifies.

VCU118 pins stay as in `fpga/vcu118/constraints/vcu118_pcie.xdc`: 100 MHz refclk on AC9/AC8, lane 0 at `GTYE4_CHANNEL_X1Y35`, lanes 0–3 of quad 227.

## Approach

Three ways were available:

1. **Soft PCS plus raw GTY PMA.** Fabric owns 8b/10b, 128b/130b, the elastic buffer, and the PIPE command plane. The GTY is a bit pipe, PLL, CDR, and analog front end. This is the plan.
2. **Soft command plane around the GTY hard 8b/10b PCS.** Smaller Gen1/2 bring-up, and the comma aligner is the silicon one. It leaves the encoder inside the primitive, which is less soft than this plan. Use it only if Slice 8 finds that `GTYE4` rejects a raw 20-bit word with the encoder bypassed. That fallback is a parameter `SOFT_8B10B` on the GTY wrapper, default 1. The PCS RTL does not change.
3. **Keep PG239.** Rejected. The VCU118 shell must stop instantiating `pcie_phy_0`.

GT Wizard IP is also rejected. It is vendor IP with a generated netlist. The wrapper instantiates the primitives directly.

## PMA port (every later slice uses this)

The PCS talks to the PMA with these ports. Names stay stable.

```systemverilog
// rtl/phy/rivet_phy_pcs.sv  (PMA side)
output logic [63:0] pma_txdata,      // meaningful bits depend on rate
output logic [5:0]  pma_txwidth,     // 20, 32, or 64
output logic        pma_txelecidle,
output logic        pma_txdetectrx,
output logic        pma_txpolarity,
output logic [4:0]  pma_txdiffctrl,
output logic [4:0]  pma_txprecursor,
output logic [6:0]  pma_txmaincursor,
output logic [4:0]  pma_txpostcursor,
output logic        pma_rxslide,     // one-cycle bit slip, Gen1/2 comma
input  logic [2:0]  pma_rate,        // same encoding as PIPE rate
input  logic [63:0] pma_rxdata,
input  logic        pma_rxelecidle,
input  logic        pma_rxdetected,  // pulsed with phystatus by the PMA
input  logic        pma_resetdone,
input  logic        pma_pll_lock
```

`pma_txdata` packing: bits `[width-1:0]` are the oldest-first line bits. Gen1/2 uses `[19:0]` as two 10-bit symbols, low symbol first. Gen3 uses `[31:0]`. Gen4 uses `[63:0]`.

## EQ contract (matches the MAC that exists today)

`rivet_ltssm` drives `txeq_ctrl = 2'b01` through Recovery.Equalization and presents a preset. `rivet_mac_pipe_adapter` drives `txeq_ctrl = 2'b10` only after `rxeq_adapt_done[0]`, and it copies `rxeq_new_txcoeff[5:0]` as the cursor it sends back. `rxeq_ctrl` is tied 0 today. The PHY still implements the full handshake so the ports behave when they are driven.

| `txeq_ctrl` | PHY action |
|-------------|------------|
| `00` | `txeq_done` low |
| `01` | Apply `txeq_preset`, drive `txeq_new_coeff`, pulse `txeq_done` for one PCLK |
| `10` | Capture three cycles of `txeq_coeff` (pre, main, post), pulse `txeq_done` on the third |
| `11` | Query. Pulse `txeq_done` and present the current coefficient. Change nothing |

| `rxeq_ctrl` | PHY action |
|-------------|------------|
| `00` | done flags low |
| `01` | Reserved. Done flags stay low |
| `10` | RX EQ. Pulse `rxeq_done`. Pulse `rxeq_adapt_done` in the same cycle on success. Leave `rxeq_adapt_done` low when the request must be repeated |
| `11` | RX EQ bypass. Same done pulses as `10`, with no cursor change |

`txeq_new_coeff` and `rxeq_new_txcoeff` pack `{pre[17:12], main[11:6], post[5:0]}`. The current MAC copies `[5:0]` and treats it as the cursor it sends back. Under this packing those six bits are the post-cursor. The PHY still uses the PG239 packing. A later MAC change can consume `[11:6]` as main. This plan does not modify `rivet_pcie_ctrl`.

Static outputs: `txeq_fs = 6'd24`, `txeq_lf = 6'd8`. Preset 4 (the guide's default) is pre 0, main 24, post 0. Preset 1, which the LTSSM sends on the normal EQ walk, is pre 0, main 20, post 4. Preset 0 is pre 0, main 18, post 6. The other presets keep pre+main+post = 24. The GTY TX precursor, main, and post ports take those three fields. Simulation does not change line bits when they change. A rate change clears the Gen3/Gen4 cursors back to preset 4.

`rivet_phy_8b10b` encodes one 8-bit symbol plus a K bit into 10 bits and updates running disparity. Decode returns the byte, the K bit, a code-error bit, and a disparity-error bit. The PCS encodes both symbols of the 16-bit PIPE word every Gen1/Gen2 cycle. On RX it scans the 20-bit PMA word for K28.5 (`10'b0011111010` or `10'b1100000101`). The buffer is nominal half-full, 16 symbols deep, per lane. A SKP ordered set is COM + three SKP (`RIVET_SYM_SKP`). The model can insert or delete one SKP symbol every N sets to imitate ppm. The gearbox writes the 2-bit sync header and then 128 data bits into the 32-bit PMA stream. Sixteen blocks are 64 data cycles plus one cycle where `txdata_valid` is low; the PCS does not read PIPE data on that cycle and does not emit a header. On RX, block lock requires two successive blocks whose header is `2'b01` (ordered set) or `2'b10` (data) and whose following 128 bits do not look like a header slip. Until lock, `rxdata_valid` is 0. After lock, `rxstart_block` is `2'b01` on the first 32-bit word of each block and `rxsync_header` carries the header. The same 64-valid-then-1-idle cadence is reconstructed on `rxdata_valid`.

Gen1/Gen2 behavior on a width-32 instance stays on bits `[15:0]`. The bench's Gen2 comma case is repeated with `PIPE_DATA_WIDTH=32` and must still pass.

**Interfaces:**
- Consumes: the PMA port from Task 1, `phy_gtrefclk` from the existing `IBUFDS_GTE4`, `sys_rst_n`
- Produces: `pclk` from `TXOUTCLK` through `BUFG_GT`, `pci_exp_txp/n`, `gt_gtpowergood`

This task is the first one that needs Vivado and the XCVU9P device. The PCS benches do not compile this file. `` `ifndef SYNTHESIS `` keeps `rivet_phy_pma_model`. `` `ifdef SYNTHESIS `` instantiates the GTY wrapper.

PLL split, confirmed against UG578 before the attributes are typed in:

- Refclk 100 MHz, `MGTREFCLK0` of quad 227, into `IBUFDS_GTE4` then the GT. A second `BUFG_GT`, clock-enabled by `gt_gtpowergood`, is `phy_refclk`.
- Gen1 uses the channel CPLL only. No `GTYE4_COMMON` for a Gen1-only build.
- Gen2 uses QPLL1. CPLL remains the Gen1 PLL and the legal Gen2 alternate. Do not use QPLL1 for Gen1.
- Gen3 uses QPLL1. Gen4 uses QPLL0. Both live in `GTYE4_COMMON`, one common for the quad.
- `TXOUTCLK` is 125 MHz at Gen1 and 250 MHz at Gen2, Gen3, and Gen4. One `BUFG_GT` drives `pclk`. A second `BUFG_GT` drives `user_clk` at 250 MHz for the x4 Gen2/3/4 shells. Rate changes mux the PCLK source only after `pma_pll_lock`.
- Reset follows the guide's order: hold CPLL/QPLL reset, progdiv reset, and TX/RX reset until `gtpowergood`; release the PLL reset and wait for lock; release progdiv reset and wait for done; release TX/RX reset, assert userrdy, wait for resetdone; hold TX sync start for four refclk cycles; then drop `phystatus` and `phystatus_rst`.
- RX equalization mode is DFE. Insertion loss is the add-in-card 20 dB setting.

Data path into the channel:

- Gen1/Gen2: 20-bit `TXDATA`/`RXDATA`, 8b/10b encoder bypassed (`TX8B10BEN` 0, `RX8B10BEN` 0), comma alignment off, `RXSLIDE` in PMA mode so Task 2's bit slip reaches the primitive.
- Gen3: 32-bit raw. Gen4: 64-bit raw. Gearbox bypassed. The fabric gearbox of Tasks 5 and 6 is the only 128b/130b.

If Vivado rejects 20-bit data with the encoder bypassed, set `SOFT_8B10B` to 0 on the wrapper only: enable the hard encoder, drive `TXCTRL0`/`TXCTRL1` with the K bits, and stop calling `rivet_phy_8b10b` for that build. Record the rejection in the commit message. Do not change the PIPE ports.

Receiver detect uses the channel `TXDETECTRX` / `RXSTATUS` detect result and feeds `pma_rxdetected`. Electrical idle uses `RXELECIDLE` and `TXELECIDLE`. Cursors from Task 7 go to `TXPRECURSOR`, `TXMAINCURSOR`, `TXPOSTCURSOR`. `TXDIFFCTRL` takes `pma_txdiffctrl`.

Placement: lane 0 `GTYE4_CHANNEL_X1Y35`, lanes 1–3 the next three channels of that quad, matching `vcu118_pcie.xdc`.
